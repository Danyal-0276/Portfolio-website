Audit date: 2026-11-13
Production URL: https://danyal.portfilio.live/

EXECUTIVE SUMMARY

The site has a strong visual identity, useful original project content, semantic sections,
descriptive image alternatives, responsive images, HTTPS, and a clean single-page URL structure.
The live Lighthouse audit scored SEO 100, Best Practices 100, and Accessibility 93. However,
the live deployment advertises a protected Vercel preview hostname in Open Graph metadata,
sitemap.xml, and robots.txt. It also has no canonical link or structured data. Those domain
signals should be corrected before submitting the new domain to search engines.

IMPORTANT DOMAIN NOTE

The exact hostname is "danyal.portfilio.live" (with "portfilio" in that spelling). This report
and the implementation intentionally use the hostname exactly as supplied. HTTPS works, and
plain HTTP permanently redirects to HTTPS. DNS currently resolves through Vercel. A www host
does not resolve and is unnecessary because danyal.portfilio.live is already a subdomain.

Vercel also assigns the valid production alias portfolio-website-six-orcin-28.vercel.app. Having
both entries marked "Valid Configuration" is normal: they point to the same deployment. The
custom domain is the canonical address, and this repository permanently redirects requests from
the Vercel production alias to the custom domain to prevent duplicate-domain signals.

CONTENT RECOMMENDATIONS — HIGHEST FUTURE SEO RETURN

1. Add a permanent page for each substantial project, for example /work/trak and
   /work/restaurant-os. Include the problem, constraints, personal contribution, architecture,
   decisions, measurable outcome, screenshots, and repository/live links. Add every page to the
   sitemap and give it unique title, description, canonical, Open Graph data, and JSON-LD.
2. Replace modal-only build notes with indexable case-study pages. Modals can remain as previews.
3. Publish occasional technical notes about work already demonstrated: transformer evaluation,
   multi-tenant authorization, RAG retrieval decisions, Stripe webhook reliability, and
   offline-first React Native storage. Prioritize quality over posting frequency.
4. Link to the portfolio from GitHub, LinkedIn, résumé PDFs, email signature, and project READMEs
   using the same canonical URL. Consistent entity links are more valuable than keyword stuffing.
5. Add measurable outcomes where truthful: latency, test coverage, users, model dataset size,
   deployment count, accuracy comparisons, or time saved. Explain personal ownership on team work.
6. Keep the research status accurate. When the paper receives a public DOI or preprint URL, add a
   dedicated publication link and ScholarlyArticle structured data.

PRODUCT AND TRUST RECOMMENDATIONS

- Buy a personal apex domain when practical (for example a .dev, .me, or .com you directly own).
  A free provider subdomain works, but an owned domain is more portable and supports branded email.
- Use a verified-domain sender for the contact form. Test successful and failed delivery after
  every email-provider or DNS change.
- Add privacy-friendly analytics or Vercel Web Analytics and measure useful actions: project opens,
  résumé downloads, GitHub/LinkedIn exits, and successful contact submissions.
- Add a short privacy notice if analytics or additional personal-data collection is introduced.
- Move rate limiting for the contact endpoint from memory to a shared store before traffic grows.
- Keep dependencies updated monthly and enable GitHub Dependabot/security alerts.

PERFORMANCE RECOMMENDATIONS

- Run mobile PageSpeed Insights after deployment and monitor field Core Web Vitals in Search
  Console; local desktop measurements are not substitutes for real-user data.
- The page is visually rich and long. Continue lazy-loading below-the-fold images and avoid making
  every image high priority. The wordmark and hero portrait are the only current priority images.
- Re-test animation work on mid-range mobile hardware. Prefer transforms/opacity and preserve the
  existing reduced-motion mode.
- If the homepage grows, move full project details to separate routes to reduce initial JavaScript,
  DOM size, and image discovery work.

SEO PRACTICES TO AVOID

- Do not add a meta-keywords tag; modern search engines ignore it.
- Do not create many thin pages that repeat the same portfolio copy.
- Do not put fragment URLs such as #work in the XML sitemap.
- Do not change lastmod on every request unless content actually changed.
- Do not purchase backlinks or repeat job-title keywords unnaturally.
- Do not expose report.txt publicly for SEO. This repository-level report is documentation;
  robots.txt is the crawler-facing standard.
